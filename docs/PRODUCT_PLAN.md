# 产品组织与实施起点

2026-11-05。用户目标：将整套生产能力复制为产品，交给客户安装到WorkBuddy等智能体宿主后独立使用。用户将项目组织方式交由主Codex判断，本轮选择独立产品目录。

## 为什么独立

视频平台承载日常生产、账号会话、冻结任务、历史回执和持续内容打磨。客户产品要处理安装、客户配置、宿主差异和升级，变更目标不同。独立目录能单独验证与交付，避免产品适配打断日常生产。

保留单一产品项目，核心、宿主与知识不再拆成多个新仓库；以后同一功能改动可以在一个地方完成代码、安装与回归。现有codex-operating-kit主要提供Codex协作声明，unified-agent-task-runtime主要规划多入口后台任务；本轮不把视频产品并入它们，也不改造它们。

本轮创建的是本地产品目录，不是现有仓库的worktree；没有创建新聊天、提交、远端仓库或后台服务。

## 产品第一版包含什么

以当前视频生产链为第一条端到端产品能力：客户资料与能力知识→选题与研究→方向与口播→配音字幕→动画→声音→整片审看→封面与交付→反馈沉淀。各部分逐步实现，第一项可验证交付不等于第一版完整完成。

客户第一次使用时提供自己的企业、服务、受众、业务资料及所需账号。产品指导初始化独立知识节点与工作区，再让每步读取相关要求、事实和案例；用户反馈定位到相应节点，成为以后创作的依据。

开发者的实际方法和质量要求作为产品基准。个人账号定位、自己的项目能力、Notion节点和历史客户材料不作为所有客户的默认事实。客户的品牌与业务价值需要由客户材料支持。

## 一个产品里的分工

| 部分 | 职责 | 首次实际实现时验证什么 |
| --- | --- | --- |
| engine | 生产阶段、工作单、产物、进度及续跑，调用真实制作能力 | 已完成的付费步骤不会因切换宿主或重启而重复执行 |
| hosts/workbuddy | 安装说明、任务上下文、工具调用与创作者派发适配 | 在实际WorkBuddy里读到正文、正确调用、保存进度并取回结果 |
| hosts/codex | 同一产品核心的Codex入口 | 可复用当前经验，避免维护另一份独立生产实现 |
| knowledge | 产品方法、节点规范、客户知识初始化与反馈机制 | 要求和材料进入实际阶段输入，反馈写回并读回核对 |
| setup | 依赖诊断、安装、客户配置、升级与迁移 | 不依赖开发者目录；缺项说清；升级保留客户数据和可用版本 |

这张表是职责设计，实际实现见[执行图](EXECUTION.md)。模型的创作、编排与判断职责沿来源设计保留；在目标宿主上的实现、模型可用性和质量另作验证，不把 WorkBuddy 内置模型当作当前指定创作者的等价替代。

## 从现有项目提取什么

| 来源 | 可复用基础 | 产品化需要处理的绑定 |
| --- | --- | --- |
| 内容总览、研究方法与模型职责 | 业务研究、材料选择、两步口播、创作与验收经验 | 客户业务配置，以及owner在不同宿主的调用方式 |
| direct-run与原阶段入口 | 任务冻结、阶段交接、状态与续跑基础 | 生产checkout身份、机器环境、宿主工具与个人配置 |
| scene-project与动画工作单 | 完整音轨、对齐、分段顺序创作、统一渲染 | Codex专用collaboration调用与真实创作者配置 |
| project-knowledge | 实际正文导入、版本绑定、按阶段分发与反馈防重 | 个人Notion节点、连接器工具名称和客户知识库初始化 |
| 音乐、声音、渲染和发布 | 真实素材、技术检查、作品与提交回执 | 目标机器依赖、客户自己的素材/账号，以及运行成本 |

来源文件和初始指纹见source-baseline.json。源码提取前以当前来源核对；本轮没有复制运行数据或制作资源。源项目仍继续自己的生产，产品运行时不得导入源项目绝对路径作为长期实现。

## 下一步顺序

1. 逐项核对宿主、模型、工具、知识读写、媒体依赖和客户配置，形成实际兼容性清单；不能只把SKILL.md搬过去。
2. 先实现客户工作区初始化、知识节点模板，以及各阶段真实正文读取与反馈回写；用虚构测试企业验证不同客户资料独立。测试身份明确，不能当真实客户结果。
3. 选择一条最小生产纵向链路迁入本产品，通过WorkBuddy实际调用和恢复来验证核心与宿主边界，再逐步接配音、动画、声音、渲染和交付。中间交付逐项标识能力范围，不把文字链验证称为整套视频产品完成。
4. 第一版完整链路在独立机器验收，包括首次安装、客户配置、真实产物、失败续跑、反馈沉淀及升级后资料保留；外部账号、付费步骤与发布按明确授权验证。

安装包不能依赖这段聊天、开发者的Codex记忆、开发者的个人Notion和磁盘路径。用户应能从产品自己的说明、配置和知识理解并执行任务。
